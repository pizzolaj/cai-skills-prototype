CAI Skills baseline study

Researcher setup page. Participants only get the start URLs. Each start URL opens a clean copy of the shipped Skills experience. Every screen change adds &screen=… to the URL, which Maze records as a step.

Objectives

  1. Map how pilot users discover, install, and trigger skills.
  2. Find where the mental model breaks: personal vs. Enterprise (locked), auto-trigger vs. /command.
  3. Find the scenarios where people want a skill vs. a one-off prompt.
  4. See what non-technical users do when a skill's output is weak and the fix is in Python, and what help would get them unstuck.
  5. Produce a prioritized list of UX changes for creation, the Enterprise directory, and weak output, backed by task data.

Maze setup

  1. Make two studies from the same blocks: Version A and Version B. Send each to a random half of the 500 pilot users.
  2. For each task, add a Website test block, paste the start URL, and paste the task text.
  3. Record the expected path by clicking through it once. Add the alternates as extra success paths.
  4. Add the follow-up questions straight after each task.
  5. S2 sits after A1, so A1 is answered before the word "skill" is defined by any options. People who answer "Never" or "I'm not sure what a skill is" skip A2–A3 (Maze condition on S2).
  6. A4 and A5 are in Version B only. In Version A they would prime the locked and invoke tasks.
  7. Screen recording is on and responses are desktop only in both studies.
  8. Maze has no task-order randomization, so task order is fixed. Report it as a limitation.
  9. Preview end to end, then pilot with one colleague before sending.

Tasks

Moderated sessions

6–8 sessions, 45 minutes, on live CAI 2.0. Recruit from C2 = Yes: 2–3 who created a skill, 2–3 who only used Enterprise skills, 2 who said they're not sure what a skill is.

TourShow me a skill you used recently. Walk me through the last time: where you found it, how you started it, what you got back.1, 3
PredictionsOn their own Skills page: "If you typed ___, would this skill run?" "Could you change this Enterprise skill? How?" Ask for the prediction first, then check it together.2
SortList the requests you repeat. Sort them into "would make a skill" and "wouldn't." Why?3

ConceptsShow 2–3 rough concepts: a plain-language diagnosis of what went wrong, CAI proposing a fix with a before/after to approve, routing the problem to the skill owner. React and rank.4
